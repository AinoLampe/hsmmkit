# Release 0.2.0

Status: released with tag `v0.2.0`. CI evidence below is for commit `486722b` (the last code change in this
release; the two commits after it only touch documentation). Run links point to the (private) GitHub repository
`AinoLampe/RegimeDetectionAndForecast`.

## What is new

- **Several price series (E9-T01).** `data.primary.symbols` may list more than one symbol. The first symbol is
  the primary and defines the time grid; every series has its own emission parameters (or shares them with
  `model.emission.per_series: false`), and a missing print masks only that series. Single-series results are
  unchanged: the recorded `M = 1` log-likelihoods and posteriors agree bitwise on the recording machine
  (`tests/golden/test_e9_t01_m1_unchanged.py`).
- **EM cross-check (E5-T06).** `regimekit.estimation.em.em_fit` runs Baum-Welch for the covariate-free GBM model
  with geometric or negative-binomial durations. It agrees with MAP (`use_priors: false`) within 1e-4 relative
  log-likelihood and 1e-2 relative sigma on the two-state test sets. It is a Python API only (no CLI or config key).
- **Design spikes, experimental and unwired:** a factorial (multi-chain) state space with the `ApproxInference`
  protocol (E9-T02, ADR-0008 finalised), an MS-GARCH emission with a carry branch in the engine (E9-T03,
  ADR-0022), and the proposal to model covariates as emission channels (E9-T04, ADR-0023). None of them has a
  config key or CLI command; see the ADRs for scope and limits.

See `CHANGELOG.md` for the user-visible changes.

## Known limitations

- The 2026-10-26 nightly [40292917653](https://github.com/AinoLampe/RegimeDetectionAndForecast/actions/runs/40292917653)
  failed its benchmark gate on `486722b` (explicit Viterbi, parallel-scan forward-backward and the L-BFGS fit
  budget were 34 to 40 % above the baseline). The six nightlies since then passed on the same commit, so the
  failure was not reproduced; if it returns, re-record the baseline only after confirming the runner image changed
  (`scripts/make_benchmark_baseline.py`).
- `ProductEmission` wraps one family for all series; a different family per series is not available. BIC's
  observation count and the starting-value strategies treat a step as observed only when every series is.
- EM supports two or more regimes only for the covariate-free GBM model on a constant time step; the EM tests
  cover two regimes.
- The MS-GARCH family is single-series, cannot simulate, forecast or score one step at a time, and is not
  registered under a config name.
- The factorial prototype handles independent single-phase chains (`r = 1`); coupling is a hook only.
- The limitations of 0.1.0 that are not listed here still apply (see `docs/releases/0.1.0.md`).
