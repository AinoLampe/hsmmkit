## Known limitations of 0.1.0

- Explicit-duration engine with a free Gamma shape: the mean-sojourn category is report-only in the
  recovery suite (weak identifiability at the sample sizes tested, see the validation guide).
- The first forecast step uses the last observed covariate row; the covariate that is known at the origin
  is not used yet.
- A pinned `data.cache.snapshot` cannot be combined with covariates (one id names one cache entry).
- Weekday calendar only for forecast dates (no holiday calendar).
- GPU tests and the CI timing of the recovery smoke and weekly jobs have not been run on CI hardware.

## Cutting the release

1. Fill in the *pending* cells above with the CI links, dates and commits.
2. `uv run towncrier build --version 0.1.0` collects `changelog.d/` into `CHANGELOG.md` (check with
   `--draft` first), and bump `version` in `pyproject.toml` from `0.1.0.dev0` to `0.1.0`.
3. Commit with a conventional message, then `git tag v0.1.0` and push the tag. The
   `.github/workflows/release.yml` workflow builds the sdist and wheel and attaches them to a GitHub
   Release; publishing to PyPI is a manual, opt-in step of that workflow.

`[tool.semantic_release]` in `pyproject.toml` (conventional commits, `v{version}` tags, `0.y.z`) is configured for
later releases; 0.1.0 is cut by the manual steps above. Its dry run was not completed here (no `origin`
remote), and the pre-release version string `0.1.0.dev0` is not strict semver, so bump it first.
